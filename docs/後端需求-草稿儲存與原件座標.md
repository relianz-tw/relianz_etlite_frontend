# 後端需求：開帳草稿儲存、原件檔案、辨識座標

前端開帳精靈要做兩件事，目前都只能存在瀏覽器本機，需要後端配合才能做完：

1. 表單即時儲存，換裝置也能接著填。
2. 申報書原件對照：點表單欄位時，在原件圖片上框出該欄位位置。

前端現況：表單資料存 `localStorage`、原件圖片存 IndexedDB，每 30 秒自動儲存，另有手動儲存按鈕。只能同一台裝置續填。

---

## 1. 辨識結果加欄位座標（`POST /ael/peit/cit/identify`）

`forms[].fields[]` 與 `forms[].rows[].fields[]` 的每個欄位，請多回兩個欄位：

| 欄位 | 型別 | 說明 |
|------|------|------|
| `page` | int \| null | 欄位在上傳檔案的第幾頁，從 1 起，對應 PDF 頁序 |
| `bbox` | object \| null | 欄位值在該頁上的位置，以對角兩點表示：`{ "x1": 0.2, "y1": 0.18, "x2": 0.7, "y2": 0.21 }` |

`bbox` 規則：
- 一律用 **0 到 1 的相對座標**，原點為頁面左上角，x 往右、y 往下增加。
- `(x1, y1)` 固定為框的**左上角**，`(x2, y2)` 固定為**右下角**，且 `x2 > x1`、`y2 > y1`。
- 相對座標才能不受前端圖片大小、放大縮小影響。
- 框住的是**欄位的值**（例如營業種類那一格的內容），不是整列標題。
- 辨識不到位置時 `page`、`bbox` 回 `null`，前端就不畫框。
- 上傳的若是單張圖片，`page` 固定為 1。

補充（建議）：`forms[]` 層級另回 `pages: int[]`，表示該份表單落在哪幾頁，前端可直接跳到那一頁。

## 2. 草稿存取

存放整份開帳表單狀態，供換裝置續填。

| 動作 | 建議路徑 | 說明 |
|------|----------|------|
| 儲存 | `PUT /ael/initialization/draft` | 覆寫該公司的草稿 |
| 讀取 | `GET /ael/initialization/draft?companyUuid=` | 沒有草稿回空 |
| 刪除 | `DELETE /ael/initialization/draft` | 開帳完成時由 `/ael/initialization/complete` 順便清除也可以 |

儲存 request：

| 欄位 | 說明 |
|------|------|
| `companyUuid` | 公司 UUID |
| `step`、`reportIndex` | 目前所在步驟與逐頁索引，回來時直接跳到那裡 |
| `state` | 前端整份表單狀態，**整段 JSON 原樣存、原樣回**，後端不需要解析內容 |
| `baseVersion` | 前端上次讀到的版本號，用來偵測衝突 |

儲存與讀取 response 都請回：`savedAt`（伺服器時間，前端直接顯示「上次儲存」）與 `version`（每次儲存遞增）。

衝突處理：`baseVersion` 比伺服器目前版本舊時回錯誤碼（例如 `409`），並附上伺服器最新的 `savedAt`，前端會提示使用者「另一個裝置已更新」讓使用者選擇。

## 3. 原件檔案存取

使用者上傳的申報書 PDF 或圖片要留存，換裝置後才能重新顯示對照面板。目前 `identify` 標明「不寫庫」，檔案辨識完就丟了。

| 動作 | 建議路徑 | 說明 |
|------|----------|------|
| 上傳 | `POST /ael/initialization/draft/files` | multipart：`companyUuid`、`file`、`kind` |
| 列表 | `GET /ael/initialization/draft/files?companyUuid=` | 回 `fileId`、檔名、大小、`kind`、上傳時間 |
| 下載 | `GET /ael/initialization/draft/files/{fileId}` | 回原檔 |
| 刪除 | `DELETE /ael/initialization/draft/files/{fileId}` | |

- `kind` 先列：`REPORT_SOURCE`（申報書原件）、`VAT_PERIOD`（401／403 某期別的申報書，需帶 `periodKey`）。
- 前端目前單檔上限 5MB，請確認後端上限。
- 前端會在本機把 PDF 轉成每頁一張圖，所以後端存原檔即可。

辨識結果（含座標）也要能在換裝置後取回，二選一：
- **A**：辨識結果放在草稿的 `state` 裡，前端自己存。
- **B**：`identify` 改成可以帶 `fileId`，後端回上次辨識的結果，不用再跑一次 AI。

我們傾向 **A**，後端不用改動辨識流程。

---

## 4. 請後端確認的事

1. 草稿與原件檔案的保留期限（例如開帳完成後多久刪除）。
2. 同一間公司是否會有多人同時填寫？衝突處理要不要比上面更嚴格。
3. 草稿與檔案的存取權限，是否沿用現有 `companyUuid` 驗證。
4. 檔案大小與頁數上限。
