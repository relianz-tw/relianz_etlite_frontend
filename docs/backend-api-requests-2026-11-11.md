# 開帳 metadata 與紙本不一致處（損益及稅額計算表，formNo 2）

整理日期：2026-11-11。對象：`/ael/peit/form/metadata`（formNo 2，損益及稅額計算表）。
規格依據：`docs/開帳文件修改.md`（G1 欄位屬性、2.4 營業收入調節說明等，各段落另述）。

## 問題

損益及稅額計算表第 03 欄「銷貨折讓」是營業收入的減項（04 營業收入淨額 ＝ 01－02－03），
紙本第 02 欄印「減：銷貨退回」，第 03 欄雖然沒印「減：」，語意上同樣是減項。
目前畫面上 03 沒有被當成減項（02 的「減：」是 `displayName` 本身帶的文字），請確認 03 的 `isDeduction` 並補上。

規格 G1 已說明：「減項的語意標記（紙本沒印『減：』的也要標）」。

## 需要後端調整

| 表 | 欄位 | 紙本欄號 | 現況 | 應為 |
|----|------|----------|------|------|
| 損益及稅額計算表（formNo 2） | 銷貨折讓（BOOK、ADJ 兩個欄位） | 03 | `isDeduction: false` 或未回傳 | `isDeduction: true` |

- BOOK（帳載結算金額）與 ADJ（自行依法調整後金額）兩個欄位都要標。
- `displayName` 改為「減：銷貨折讓」（BOOK、ADJ 兩個欄位都改）。前端一律以 `displayName` 為準、不自行補「減：」前綴，
  畫面上要看出是減項，只能靠 `displayName` 帶「減：」，與 02「減：銷貨退回」一致。
- `formula` 不變（04 仍為 `INC_01 - INC_02 - INC_03`）。

## 請順便全表檢查

紙本沒印「減：」、但語意為減項的欄位，請整份 12 張表掃一次，比照 03 補上 `isDeduction: true`。
前端不自行判斷減項，完全依後端回傳；這類欄位的 `displayName` 也請一併加上「減：」前綴。

## 前端處理

前端目前只拿 `isDeduction` 當該列的 aria-label（「（減項）」），畫面上沒有視覺標示；
畫面上的「減：」前綴由 `displayName` 提供，所以兩者都要改，前端不需再動。

# 營業收入調節說明：加項／減項 `groupCode`

## 問題

規格（`docs/開帳文件修改.md` 2.4.1）要求調節說明區的欄位帶 `groupCode`，讓前端標示「加項」「減項」。
staging 2026-11-10 實測（見 `backend-api-requests-2026-11-10.md` 第 6 項）：RECON 區欄位的 `groupCode` 全是 `null`，
前端因此無法分出加項、減項，畫不出標題，也無法折疊。請後端確認現況，仍為 `null` 者補齊。

## 需要後端調整

| `groupCode` | 欄位 |
|-------------|------|
| `RECON_SUMMARY` | `INC_68`、`INC_69` |
| `RECON_ADD`（加項） | 70、71、72、73、74、75、`INC_75_NOTE` |
| `RECON_SUB`（減項） | 76、77、78、86、80、81、82、83、84、85、88、100、98、87、`INC_87_NOTE` |
| `RECON_RETURN` | `INC_128`、`INC_128_NOTE` |

- 排列順序維持紙本順序（86 在 78 後面、98 在 100 後面）。
- **`visibleWhen` 請移除**：規格原本要求加減項帶 `visibleWhen: { fieldCode: "INC_69", op: "nonZero" }`（69 為 0 時隱藏）。
  產品改為「加項、減項欄位一律顯示」，只由前端依 69 的正負折疊用不到的那一組（69 大於 0 折疊減項、小於 0 折疊加項），
  所以 `RECON_ADD`、`RECON_SUB` 的欄位不需要 `visibleWhen`。前端目前對這兩個 `groupCode` 的欄位會忽略 `visibleWhen`，
  但仍請後端移除，避免兩邊規則不一致。
- 說明欄掛主欄位：`INC_75_NOTE.parentFieldCode = INC_75`、`INC_87_NOTE.parentFieldCode = INC_87`、`INC_128_NOTE.parentFieldCode = INC_128`。

## 標題文字

metadata 只有 `groupCode`，沒有標題文字。前端目前把 `RECON_ADD` 顯示為「加項」、`RECON_SUB` 顯示為「減項」（寫在前端），
`groupCode` 值請勿更動。若後端之後能在 metadata 提供分組標題（例如 `groups[]`：`{ groupCode, title }`），前端可改為讀取，不再寫死。

# 128「銷貨退回及折讓差異情形」要獨立成區塊並帶標題

## 問題

紙本在「營業收入調節說明」下方，另有一個自己的區塊，標題為：

> 總分支機構申報營業稅銷售額之銷貨退回及折讓差異情形

區塊內容是一句話：「128 營業稅申報銷貨退回及折讓金額 ＿＿元，與本頁 02 銷貨退回及 03 銷貨折讓之差異說明：＿＿」。

staging 實測畫面：這句話（`INC_128`、`INC_128_NOTE`、對應的 `textBlocks`）併在「營業收入調節說明」區塊最下面，沒有標題、沒有分隔。
規格 2.4.1 只把它定為 `groupCode: RECON_RETURN`（「另成一塊」），但 `groupCode` 不會產生區塊標題與分隔線；
前端的區塊標題與分隔只依 `sections[]`。

## 需要後端調整

1. `sections[]` 新增一個區塊，例如：

```json
{ "sectionCode": "RECON_RETURN", "title": "總分支機構申報營業稅銷售額之銷貨退回及折讓差異情形", "parentSectionCode": null }
```

2. `INC_128`、`INC_128_NOTE` 的 `sectionCode` 改為該區塊（不再是 `RECON`）。
3. 128 那句話對應的 `textBlocks` 項目，`sectionCode` 也設為該區塊。
4. 區塊順序：緊接在 `RECON`（營業收入調節說明）之後、「揭露事項」之前。前端依欄位在 `fields[]` 第一次出現的位置排區塊，
   請讓 128 欄位排在 `RECON` 其餘欄位之後、揭露事項欄位之前。

前端不需要再改，區塊標題與分隔線會依 `sections[]` 自動畫出。

# 表頭區塊要在表單最上面，收件編號每份文件都在表頭

## 問題

紙本每份文件最上方是表頭（所得期間、營利事業名稱、統一編號、組織種類、收件編號等，沒有區塊標題）。
staging 實測畫面：表頭欄位在 `fields[]` 的位置排在文件內容之後，所以表頭區塊出現在整張表最下面
（損益及稅額計算表、基本稅額、未分配盈餘、扣繳調節等多份都是）。
規格 G1：區塊順序依其第一個欄位在 `fields[]` 出現的位置，前端不調整。

## 需要後端調整

1. 12 份文件的表頭欄位，在 `fields[]` 裡一律排在最前面，`sectionCode` 維持同一個區塊、`sections[].title` 為 `null`（無標題）。
2. **收件編號**每份文件都放在表頭區塊（目前有些文件不在表頭或不在最前面）。
3. 損益及稅額計算表（formNo 2）表頭內的順序：
   所得期間（起、迄）→ 申報適用房地合一稅制者 → 營利事業名稱、統一編號 → 組織種類 → 收件編號 →
   「適用產業創新條例第23條之1規定之有限合夥組織創業投資事業」勾選，**放在表頭最後**。
   其他文件的表頭欄位同樣依紙本由左到右、由上到下的順序。
